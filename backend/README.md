# Backend приложения

Этот проект представляет собой бэкэнд, созданный с использованием [NestJS](https://nestjs.com/), прогрессивного фреймворка для Node.js.

## Ключевые особенности настройки

### 1. Валидация переменных окружения

Для обеспечения надежности и предсказуемости конфигурации используется модуль `@nestjs/config` в связке с библиотекой `zod`.

-   **Схема валидации**: В файле `src/config/env.schema.ts` определена схема `EnvSchema`, которая описывает все необходимые переменные окружения, их типы и значения по умолчанию.
-   **Проверка при запуске**: При старте приложения NestJS автоматически проверяет все переменные окружения на соответствие этой схеме.
-   **Безопасный запуск**: Если какая-либо переменная отсутствует или имеет неверный формат, приложение не запустится, и в консоль будет выведено подробное сообщение об ошибке.

### 2. Поддержка нескольких окружений

Проект настроен для удобной работы в разных средах (например, разработка и продакшн).

-   **Файлы конфигурации**:
    -   При запуске в режиме разработки (`NODE_ENV=development`) используются переменные из файла `.env.development`.
    -   Во всех остальных случаях (например, в продакшене) используется стандартный файл `.env`.
-   **Автоматический выбор**: Логика выбора файла реализована в `AppModule` и не требует ручного вмешательства.

### 3. Интеграция с Prisma

Команды Prisma CLI адаптированы для работы с разными окружениями.

-   **`dotenv-cli`**: Используется для загрузки нужного `.env` файла перед выполнением команды Prisma.
-   **NPM Скрипты**: В `package.json` добавлены специальные скрипты для удобства.

## Модуль авторизации (Auth Module)

Модуль `Auth` отвечает за регистрацию, вход, выход и обновление сессии пользователя. Он использует JSON Web Tokens (JWT) для аутентификации, применяя продвинутую и безопасную стратегию **ротации токенов обновления (Refresh Token Rotation)**.

### Основные эндпоинты

-   `POST /auth/signup`: Регистрация нового пользователя.
-   `POST /auth/signin`: Вход пользователя.
-   `POST /auth/logout`: Выход пользователя из текущей сессии.
-   `POST /auth/refresh`: Обновление пары токенов (access и refresh).

### Стратегия управления токенами

При успешном входе (`signin`) или регистрации (`signup`) пользователь получает два токена:

1.  **Access Token**: Короткоживущий JWT, который предоставляет доступ к защищенным ресурсам. Он должен отправляться в заголовке `Authorization` при каждом запросе.
2.  **Refresh Token**: Долгоживущий JWT, предназначенный исключительно для получения новой пары токенов.

### Защита от атак повторного использования (Replay Attacks)

Система реализует надежный механизм защиты от кражи и повторного использования `refresh-токенов`.

#### Как это работает:

1.  **Хранение и отслеживание**: Каждый `refresh-токен` хэшируется и сохраняется в базе данных. В таблице `Token` также есть булево поле `isUsed`, которое по умолчанию имеет значение `false`.

2.  **Процесс обновления токена (`/auth/refresh`)**:
    -   Пользователь отправляет свой `refresh-токен` для получения нового `access-токена`.
    -   Система находит соответствующий хэш токена в базе данных.
    -   **Счастливый путь**: Если токен найден и его флаг `isUsed` равен `false`, система считает запрос легитимным. Она немедленно помечает этот токен как `isUsed: true` и создает новую пару токенов (access и refresh). Новый `refresh-токен` также сохраняется в базу данных со статусом `isUsed: false`. Эти операции выполняются в рамках одной **атомарной транзакции**, что исключает гонку состояний.
    -   **Обнаружение атаки**: Если система получает `refresh-токен`, который уже помечен в базе как `isUsed: true`, она расценивает это как атаку повторного использования.

3.  **Автоматический ответ на атаку**:
    -   В случае обнаружения атаки система немедленно **удаляет все** активные `refresh-токены` данного пользователя из базы данных.
    -   Это действие принудительно завершает все его сессии на всех устройствах.
    -   Злоумышленник (и легитимный пользователь) теряет доступ и должен заново пройти аутентификацию (ввести логин и пароль).
    -   Клиенту возвращается ошибка `401 Unauthorized`.

Эта стратегия гарантирует, что даже если `refresh-токен` будет украден, его можно будет использовать только один раз. При любой попытке повторного использования система заблокирует сессию, предотвращая несанкционированный доступ.

## Начало работы

### Установка зависимостей

```bash
npm install
```

### Переменные окружения

1.  Создайте файл `.env.development` в корневой директории `backend/`.
2.  Заполните его необходимыми переменными для среды разработки.

**Пример `.env.development`:**

```env
# Режим работы (уже устанавливается через cross-env)
NODE_ENV=development

# Настройки сервера
PORT=3001
HOST=localhost

# URL для подключения к базе данных
DATABASE_URL="postgresql://user:password@localhost:5432/mydb_dev?schema=public"

# Секреты для JWT
AT_SECRET="your-access-token-secret"
RT_SECRET="your-refresh-token-secret"

# Время жизни токенов
AT_EXPIRES_IN=900 # 15 минут
RT_EXPIRES_IN=604800 # 7 дней
```

3.  Аналогично создайте и настройте файл `.env` для продакшн-среды.

## Запуск приложения

### Режим разработки

Запускает приложение с автоматической перезагрузкой при изменениях кода. Использует `.env.development`.

```bash
npm run start:dev
```

### Продакшн режим

Сначала соберите проект:

```bash
npm run build
```

Затем запустите собранное приложение. Использует `.env`.

```bash
npm run start:prod
```

## Работа с базой данных (Prisma)

### Генерация клиента Prisma

После изменений в `prisma/schema.prisma` выполните:

```bash
npm run prisma:generate
```

### Миграции (Разработка)

Для создания и применения миграций в среде разработки (используя БД из `.env.development`):

```bash
# Создать новую миграцию с именем 'init'
npm run prisma:migrate:dev -- --name init
```

### Prisma Studio (Разработка)

Для просмотра и редактирования данных в БД разработки через веб-интерфейс:

```bash
npm run prisma:studio:dev
```

### Миграции (Продакшн)

Для применения существующих миграций в продакшн-среде (используя БД из `.env`):

```bash
npm run prisma:migrate:prod
```
